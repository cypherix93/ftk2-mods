# EOR v0.7.0.60 — mechanic behavior matrix (class skills, traits, affixes)

**Purpose:** exact gameplay semantics for every mechanic slated for porting, precise enough to re-express as a
data-driven skill recipe without re-reading the decompile. Source: `tools/out/decompile/EOR-0.7.0.60/FTK2/BanditKingPlayable/Plugin.cs`
(29,415 lines). All `L####` are line numbers in that file, read directly for this document (2026-07-25).

Row counts: **31** class skills + **11** code traits + **5** affixes = **47** primary rows, plus **4** hybrid
trait code-half sub-rows (TREASURE_SENSE, STEADY_AIM, WARDBOUND, SCHOLARS_HABIT) = **51** rows total.

## Legend

**Roll tiers** (`eRollStatus`, FTK2's 4-tier ability-resolution grade): `PERFECT` > `SUCCESS` > `FAIL` >
`CRIT_FAIL`. Code shorthand used below: `flag2`=PERFECT, `flag3`=SUCCESS-or-PERFECT, `flag4`=CRIT_FAIL.

**"Direct hostile ability"** = `IsDirectHostileAbility` (L6601): `ability.Target == eTargets.ENEMY` AND
`CharacterHelper.IsOpponent(origin, target)` (L6610 `AreOpponentsSafe`, wrapped in try/catch → false on error).

**RNG sources** (all class-skill/response code draws from the `GameRandom random` parameter threaded through
`CombatHelper.PerformAbility` prefix/postfix — i.e. the combat's shared, lockstep-deterministic stream; per
`eor-0760-content-audit.md` §3.2 this is the same stream every peer must stay in sync on):
- **`combat-random`** = the `random` param as received from the Harmony patch (ultimately `CombatState.Random`).
- **`RollChance(random, pct)`** (L6644) = `random.NextInt(0,100) < pct` — one draw from `combat-random`.
- **`NextChance(decimal)`** = engine helper on `GameRandom`, same stream, used in loot-postfix code.
- **`RollSelectableTraitChance(random, chance)`** (L24432) = if `random` arg is non-null, uses it; else calls
  `TryResolveGameplayRandom` (L10442) which falls back to `CombatState.Random` and, if that is also null
  (i.e. **no active combat**), to `TryCreateSharedSeededGameplayRandom` (L10474) — a **freshly constructed**
  `GameRandom` seeded from `MapGenSeed|ConfigName|ActiveMapID|EncounterGUID|RoundCount|contextKey`, not a
  continuation of any shared stream. **ARCANE_MEMORY and OF_SPELLKEEPING call this with `random: null`
  explicitly (L24462–24463)** — since scroll consumption normally happens outside combat, these two virtually
  always take the seeded-fallback path, not the lockstep combat stream.

**Vocabulary fit** (per `FTK2.ClassForge/SPEC.md` §4.6 and `eor-0760-content-audit.md` §7):
- `FITS_V1` — fully expressible with existing triggers (`ON_CRIT/ON_KILL/ON_TURN_START/ON_TURN_END/ON_DAMAGED/ON_HEAL/ON_ABILITY_USED`), conditions (`HP_THRESHOLD/HAS_STATUS/LACKS_STATUS/ROW/WEAPON_CLASS/ABILITY_TAG/TARGET_BASE_TYPE(_NOT)`), effects (`ADD_STATUS/REMOVE_STATUS/STAT_CHANGE/SUMMON`).
- `NEEDS:<tag>` — needs one or more new primitives. Tag vocabulary used in this document (tag = short name, kind, meaning):
  | Tag | Kind | Meaning |
  |---|---|---|
  | `ON_COMBAT_START` | trigger | fires once when combat-entity initiative is set (`SetInitiative` postfix) |
  | `ON_STAT_CHANGE_DEALT` | trigger | fires when the actor's action reduces a target's HP (damage dealt) |
  | `ON_STAT_CHANGE_TAKEN` | trigger | fires when the actor's own HP is reduced (damage taken) |
  | `ON_CONSUMABLE_USED` | trigger | fires on `PerformConsumableAbility` postfix |
  | `ON_DODGE` | trigger | fires when the actor dodges an incoming direct attack |
  | `ON_CRIT_FAIL_SELF` / `ON_CRIT_FAIL_ENEMY` | trigger | actor's own roll, or an opponent's roll, resolves CRIT_FAIL |
  | `ROLL_TIER(x)` | condition | gate on roll grade (PERFECT/SUCCESS/CRIT_FAIL) beyond a boolean crit flag |
  | `CHANCE_PCT(n)` | condition | independent RNG percent-chance gate, exact integer/decimal from code |
  | `ONCE_PER_COMBAT` | condition | budget flag cleared at combat entity init (`ClassSkillRuntimeState.OnceCombat` / `SteadyAimUsedThisCombat`) |
  | `ONCE_PER_ROUND` | condition | budget flag keyed to `TotalRounds` (`ClassSkillRuntimeState.OnceRound`) |
  | `ALL_ALLIES_ACTED` | condition | all other living player-tagged allies have `ActedRound == round` |
  | `STAT_STACK_THRESHOLD` | condition | reads an internal stack counter (0–3) on the actor |
  | `TARGET_TRACKING` | condition/state | remembers a specific target GUID across the actor's turns within a combat |
  | `RESOURCE_SPENT_THRESHOLD` | condition | gate on Focus spent this action (`decision.FocusUsed`) |
  | `IMMUNITY_FALLBACK` | effect | apply status A, or status B if target is immune to a named `eStatusEffectTypes` |
  | `RANDOM_ELEMENT_CHOICE` | effect | pick uniformly from a fixed status-id array via `GetRandomElementFromArray` |
  | `DAMAGE_TAKEN_MULT` | effect | multiplicatively reduce/increase incoming final damage (`CalculateFinalDamage` postfix) |
  | `HEAL_RECEIVED_MULT` / `HEAL_GIVEN_MULT` | effect | scale a heal amount before application (`AddHealth` prefix) |
  | `SUPPRESS_CONSUME` | effect | chance to cancel item consumption entirely (host-authoritative hazard, see MP notes) |
  | `STATUS_APPLY_RESIST` | effect | chance to no-op an incoming harmful status application |
  | `OUTGOING_ATK_BUFF_WINDOW` | effect | temporarily inflate the ATK value used for *this* ability roll only (delegate-wrap, not a status) |
  | `GOLD_GRANT` / `ITEM_TAG_GRANT` | effect | mint currency / a random item matching a tag into post-combat loot |
  | `FOCUS_CHANGE` | effect | add/remove Focus points |
  | `STEAL_STATUS` | effect | remove a status from target and re-apply an equivalent to self |
  | `CLEANSE_RANDOM_STATUS` | effect | remove one harmful status from a party member, alphabetically-first tiebreak |
  | `STAT_STACK_ADD` / `STAT_STACK_RESET` | effect | increment (capped) / zero an internal stack counter |
  | `CROSS_ENTITY_COORDINATION` | condition | reads another entity's `ClassSkillRuntimeState` (Beastmaster+pet) |
- `UNPORTABLE:<reason>` — not modelable as a data-driven recipe at all.

**MP hazard shorthand:** every row states whether it draws from the shared lockstep `combat-random` (safe if all
peers execute the same branch) or a fallback/other source, and whether it mutates state that must be
host-authoritative.

## Cross-cutting notes

- **`getTileStat`/`GetStat` delegate-wrapping** (`OUTGOING_ATK_BUFF_WINDOW`, used by 12 of 31 class skills:
  ASSASSIN, CORSAIR, DUELIST, PEASANT, RANGER, SCOUT, TEMPLAR, WARRIOR, WIZARD via `getTileStat` L6154–6163;
  STEADY_AIM via the `eGetStatEquippedFilters` overload L22892–22899) is architecturally distinct from a status
  effect: it only affects the stat value used for *this specific roll*, never touches persistent character
  state, and cannot be inspected/dispelled. A recipe engine needs either (a) a genuine "this-roll-only stat
  bonus" effect primitive, or (b) to model it as a 1-round self-status applied just before the roll and cleared
  just after (behaviorally equivalent but visible/dispellable, a deliberate semantic change).
- **Text/code mismatches found** (flavor description overstates or misdescribes the actual branch logic — code
  is authoritative per this document's mandate): RANCHER (no Daze fallback, only Attack Down), TRICKSHOT (no
  Daze branch, fallback is Attack Down not Evasion Down), SCOUT (Evasion Down applies on every perfect hit, not
  just the opening hit), WARDEN (excludes self from the ally buff, text doesn't say so).
- **No `UNPORTABLE` rows** — every one of the 47 primary + 4 hybrid mechanics resolves to a combination of
  existing v1 primitives and/or the tagged gap primitives above; none depend on architecture that cannot be
  re-expressed in a data-driven recipe (contrast with the dropped systems in audit §2.6/§6 row 9, which *are*
  parked as out-of-scope, not because they're unportable in principle).
- **No `UNRESOLVED` rows** — all cited line ranges were read in full and every number below is copied verbatim
  from the decompile (percentages, HP thresholds, stack caps, gold ranges, duration values, focus amounts).
